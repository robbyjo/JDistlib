Recommended first route

The complete CSV → JDM → MCMC workflow

WorkedMcmcCsvJdmExample.java is a deliberately verbose, line-by-line-commented Java program. It uses the checked-in CSV dataset and JDM model, so it runs without downloads or editing.

  1. Load and validate dataRead the named y column from CSV into a primitive double[].
  2. Load and compile the modelRead UTF-8 JDM source, bind N and y, call ModelScript.compile, and check its gradient.
  3. Configure and sampleChange warmup, retained draws, target acceptance, tree depth, metric adaptation, and progress settings; then launch four dispersed, seeded NUTS chains.
  4. Diagnose and visualizePrint R-hat, bulk/tail ESS, MCSE, acceptance, divergences, tree depth, E-BFMI, and failures; export trace, rank, ACF, and energy plots.
  5. Summarize and concludeReport the posterior mean, SD, median, interval, P(mu > 0), an exact conjugate cross-check, a posterior-predictive draw, and a conclusion conditional on convergence.
// The actual example contains explanatory comments around every operation.
double[] y = readNumericColumn(csvPath, "y");
String source = new String(Files.readAllBytes(modelPath), UTF_8);

Map<String, double[]> data = new LinkedHashMap<>();
data.put("N", new double[] {y.length});
data.put("y", y);

CompiledModelScript compiled = ModelScript.compile(source, data);
BayesianModel model = compiled.model();
SamplingOptions options = SamplingOptions.builder()
    .warmupIterations(600).sampleIterations(1200)
    .targetAcceptance(0.90).maximumTreeDepth(11)
    .adaptMassMatrix(true).denseMassMatrix(false).build();

ChainResult[] chains = Chains.parallel(
    new NoUTurnSampler(), model, initialStates,
    options, BASE_SEED, 4);
McmcDiagnosticReport report = McmcDiagnostics.analyze(
    new String[] {"mu"}, chains);
Why the example has its own CSV reader: JDistlib accepts Java values and does not impose a dataframe or CSV dependency. The small reader makes the example self-contained. Applications with quoting, delimiters, missing-value conventions, or schemas should use their normal data library and bind the resulting arrays in exactly the same way.

Run it locally

Compile the library and documentation examples

From the repository root, first compile the packaged JAR and every Java example. Use ./gradlew compileDocumentationExamples on macOS/Linux or gradlew.bat compileDocumentationExamples on Windows.

On macOS or Linux, run:

java -cp "build/libs/jdistlib-0.8.3-SNAPSHOT.jar:build/documentation-examples" \
  examples.WorkedMcmcCsvJdmExample

On Windows, run:

java -cp "build\libs\jdistlib-0.8.3-SNAPSHOT.jar;build\documentation-examples" examples.WorkedMcmcCsvJdmExample

The three optional arguments are CSV_PATH JDM_PATH OUTPUT_DIRECTORY. Omitting them uses the checked-in files and writes to build/worked-mcmc.

Compilation has two meanings here: Gradle compiles the Java example. At runtime, ModelScript.compile(source, data) parses, checks, and lowers the JDM model into a usable BayesianModel; no separate Stan toolchain or generated Java source is required.

Review the analysis

Use numbers and plots together

The seeded checked-in dataset produces a posterior mean near 0.22, posterior SD near 0.35, and a 95% interval that crosses zero. The exact conjugate posterior mean and SD are printed beside the Monte Carlo estimates as an end-to-end cross-check. Small last-digit changes may occur across runtime implementations.

Healthy computation

The example requires all chains to succeed and interprets R-hat, bulk/tail ESS, divergences, maximum tree depth, E-BFMI, and numerical failures together. A healthy diagnostic screen means the Monte Carlo calculation is credible; it does not force a scientific effect to exist.

Evidence in this dataset

The example separately evaluates the interval and P(mu > 0). With the checked-in observations, the sensible conclusion is that computation looks healthy but the posterior retains substantial uncertainty around zero.

The output directory contains reviewable artifacts:

  • mu-trace.svg — chain mixing and stationarity;
  • mu-ranks.svg — whether chains occupy comparable posterior ranks;
  • mu-autocorrelation.svg — serial dependence by lag;
  • energy.svg — Hamiltonian energy behavior;
  • retained-draws.csv and diagnostics.json — machine-readable results; and
  • report.html — a self-contained report with diagnostics and plots.
Do not report the conclusion first: only interpret posterior summaries after checking chain status and diagnostics. If chains disagree, divergences occur, or E-BFMI is poor, fix the computation before interpreting the interval.
